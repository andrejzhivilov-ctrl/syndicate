# Перенесення ідей Make у n8n

## Коли застосовувати
Коли потрібно зрозуміти або переосмислити автоматизаційний сценарій з Make для нашої n8n-орієнтованої архітектури.

## Переносимі концепції
- Router/filters → розгалуження з явними умовами.
- Iterator/aggregator → контрольована робота з колекціями та збір результатів.
- Webhook/HTTP → контрактований вхід і allowlisted запит.
- Data store → явне визначення власника, retention, схеми й idempotency.
- Error handling → окремий маршрут помилки, обмежені retries та аудит без payload/секретів.

Це поняттєві відповідності, не гарантія однакової семантики модулів. Перед реалізацією звірити обмеження, типи даних, retry semantics та ліцензію/план обох платформ.

## Межі
Make-специфічний runtime не підключений. Не створювати Make credentials і не активувати сценарії; n8n workflow також лишається неактивним до окремого дозволу.

## Джерела й статус
Синтез за 24 уроками прикріпленого Make курсу. Нумерація уроків повторюється в різних блоках; потрібне структурне нормалізування. Чернетка для Marshal.

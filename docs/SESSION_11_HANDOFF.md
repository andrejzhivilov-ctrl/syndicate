## 7. Обов'язкові обмеження (не порушувати)

З `AGENTS.md` (контракт, порушувати не можна):

* **Ніколи не вигадувати дані.** Відсутність = `{"status": "unavailable", "value": None, "warning": ...}`,
  ніколи не `ok`. Демо-дані — лише з `synthetic: True` + warning і за явним env-прапорцем.
* **Ніколи не «лагодити» тест під себе** — кожен тест фіксує реальний виправлений дефект.
* Людина (Андрій) погоджує будь-яку дію з грошима, торгівлею, видаленням, публікацією
  (`src/confidence.py` → `NEVER_AUTO_ACT`).
* Межі каталогів: `apps/` — **тільки Antigravity**; `src/ deploy/ tests/ config/` — **тільки Arena Agent**.
  `apps/shared/api-contract.yaml` генерується з бекенду (власник — Arena Agent, Antigravity — споживач).
* Ніколи не редагувати `main` одночасно з іншим агентом; кожна зміна — своя гілка; у `main`
  потрапляє лише зелене за `tools/check.sh`.
* Документи й звіти — українською; код, коментарі, ідентифікатори — англійською; коміти — англійською.
* `datetime.utcnow()` заборонено — лише `datetime.now(timezone.utc)`.
* Записувані файли — лише через `src/data_paths.py` (`EVA_DATA_DIR`); секрети — лише через
  `src/vault_paths.py`; PII маскується перед зовнішнім LLM (`src/pii.py`); пошта — чернетки без відправки.
* **Комітити й пушити негайно** — пісковиця скидається між сесіями.
* `main` — кінцевий пункт усіх змін; гілки, що злиті або ідентичні, видаляти.

Правила користувача, чинні досі: перевіряти працездатність **перед** новими фічами; деплой
на **сервері** (локальна машина — відхилено: «Стоп. відбій»); репозиторій **публічний**.

## 8.2. Перший запуск на сервері (усе, що не перевірялось у пісковиці)

У пісковиці немає `docker`, тому **жоден контейнер, жоден образ і жоден мережевий шлях не
перевірялися запуском** — тільки парсером Compose, тестами й читанням. На сервері це
перевіряється вперше. Піднімати стек **по одному сервісу**, щоб збій був ізольований:

```bash
cd /opt/eva
docker compose -f deploy/docker-compose.yml --project-directory . --env-file .env config -q  # синтаксис + змінні
docker compose ... up -d postgres redis vault && docker compose ... ps        # (1) інфраструктура
docker compose ... exec -T redis redis-cli -a "$REDIS_PASSWORD" --no-auth-warning ping   # NOAUTH без пароля
docker compose ... up -d embeddings && docker compose ... logs -f embeddings  # (2) ~2 ГБ ваг, хвилини
docker compose ... exec -T embeddings python -c "import urllib.request;print(urllib.request.urlopen('http://127.0.0.1:8000/health').read())"
docker compose ... up -d eva-agent && docker compose ... logs -f eva-agent     # (3) агент
curl -s http://127.0.0.1:8000/health                                          # semantic_search_enabled: true
docker compose ... up -d n8n whisper nginx                                    # (4) решта
```

Що дивитися при збої (найімовірніші місця, бо вони ніколи не виконувались):

| Симптом | Причина | Дія |
| :--- | :--- | :--- |
| `docker compose config` скаржиться на `REDIS_PASSWORD` | `${REDIS_PASSWORD:?}` навмисно валить конфіг, якщо змінної немає | заповнити `.env` |
| Помилка завантаження образу | закріплені теги (`n8nio/n8n:1.68.0`, `hashicorp/vault:1.15`, `nginx:1.25-alpine`) могли зникнути в реєстрі | перевірити тег, оновити разом із `RESOURCE_CALCULATION.md` |
| `embeddings` довго `starting` | перше завантаження ваг BGE-M3 (~2 ГБ) | `start_period: 300s`, дивитись логи |
| `embeddings` unhealthy | немає egress або диск повний | перевірити `HF_HOME=/app/model_cache` (volume `embeddings_data`) |
| Стек піднімається, але `semantic_search_enabled: false` | `EMBEDDINGS_URL` порожній | пам'ять працює; увімкнути URL і перезапустити агента |
| `vault_init.sh` просить замінити `CHANGE_ME_*` | так і задумано — це пункт 32 (Vault) | див. наступний крок |

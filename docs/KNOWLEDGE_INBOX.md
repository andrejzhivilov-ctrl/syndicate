# Канал знань: як завантажувати матеріали в бази агентів і Obsidian

Рішення Андрія від 18.11.2026: один канал для всього холдингу, а порядок наводить Єва.

## Як закинути матеріал

| Шлях | Для чого | Розмір |
|---|---|---|
| Google Drive → «SYNDICATE» → «Вхідні на опрацювання» | будь-що з будь-якого пристрою: книги, курси (теками), відео, таблиці | до 2 ГБ на файл |
| Telegram → бот Єви | швидко скинути файл із телефона | до 20 МБ (ліміт Telegram) |
| Google Drive → «Вхідні» в «SYNDICATE Алекс» | лише для Алекса, як і раніше | до 2 ГБ |

Сортувати самому нічого не треба. Тека в «Вхідних» означає курс: вона переїде цілою.

## Що відбувається далі

1. Кожні 10 хвилин нове з Drive копіюється в Obsidian `00_Inbox/Вхідні` (задача `eva_drive_inbox`). Файли з бота Єви потрапляють туди одразу.
2. Через 3 хвилини Єва (`eva_sort_materials`) визначає власника кожного файлу чи курсу:
   - Алекс → `Health_Coach/Матеріали`;
   - Сем → `Сем/Матеріали`, Тайлер → `Тайлер/Матеріали`, Фін → `Фін/Матеріали`, Кіра → `Кіра/Матеріали`, Маршал → `Маршал/Матеріали`;
   - загальне → `09_База_Знань/Матеріали`;
   - не зрозуміла → `00_Inbox/На перевірку`, і Єва пише, що чекає твого слова.
3. Там же Єва розкладає файли по темах агента й переписує його `Каталог.md`.
4. Агент шукає спершу в каталозі, потім читає потрібне частинами. Відео й аудіо розшифровуються.
5. Щоночі все сховище потрапляє в бекап (сервер, раз на тиждень копія на SSD).

Нічого не видаляється й не перезаписується: однакові назви стають `назва (2)`, однаковий вміст іде в `_Дублікати`.

## Що треба зробити Андрію один раз

1. Створити в Google Cloud сервісний акаунт для Єви й завантажити його JSON-ключ.
2. На сервері: `python3 scripts/syndicate_vault.py set-google-sa eva <файл> --shred`.
3. На Drive у теці «SYNDICATE» є «Вхідні на опрацювання» (Єва створила її 19.11). Поділитися всією «SYNDICATE» з email сервісного акаунта Єви як «Редактор».
4. Додати `eva_drive_inbox` у `SYNDICATE_SCHEDULE` (поруч із `eva_sort_materials`) і розгорнути.

Без кроків 1–3 канал через Drive повертає `unavailable` з причиною, а бот Єви приймає файли вже зараз.

## Перед тим як зробити репозиторій приватним

Зараз сервер бере код з GitHub без ключа, як із публічного репозиторію. Після переходу в приватний `git pull` на сервері й перевірки Claude Code там перестануть працювати. Тому спершу потрібен ключ лише для читання (deploy key):

```bash
sudo -u syndicate ssh-keygen -t ed25519 -f /home/syndicate/.ssh/github_deploy -N "" -C "syndicate-server-read-only"
sudo -u syndicate cat /home/syndicate/.ssh/github_deploy.pub
```

GitHub → репозиторій → Settings → Deploy keys → Add deploy key: вставити цей рядок, **Allow write access не ставити**.

```bash
printf 'Host github.com\n  IdentityFile /home/syndicate/.ssh/github_deploy\n  IdentitiesOnly yes\n' | sudo -u syndicate tee /home/syndicate/.ssh/config
sudo -u syndicate ssh -o StrictHostKeyChecking=accept-new -T git@github.com
cd /opt/syndicate && sudo -u syndicate git remote set-url origin git@github.com:andrejzhivilov-ctrl/syndicate.git && sudo -u syndicate git pull --ff-only
```

Остання команда має пройти. Лише після цього перемикай репозиторій у Private. Приватний репозиторій усе одно не місце для секретів і особистих даних: вони лишаються у Vault і Obsidian.

## Усе стає Markdown, оригінали живуть на Google Drive (18.11.2026)

Рішення Андрія: на сервері зберігається лише Markdown, оригінали — на Google Drive (далі OneDrive або власне сховище на Contabo).

Задача `eva_markdown` (щогодини о :06, :16, …, до 5 файлів і одного аудіо чи відео за прохід) робить поруч із кожним розкладеним файлом картку `<файл>.md`:

- властивості: `summary`, назва, тема, мова, тип, розмір, **де лежить оригінал**;
- вміст: повний текст документів (PDF, Word, EPUB, TXT), таблиці Excel і CSV, слайди; розшифровка аудіо й відео з мітками часу (Deepgram з кредиту, запасний — Groq); для фото й сканів — опис і розпізнаний текст (Gemini Hydrogen, близько 0,2 цента за фото).

Потім оригінал:
- прийшов із Drive → перевіряється на Drive за його id і лише тоді видаляється із сервера;
- прийшов через бот → стискається без втрат (PNG перепаковується, WAV → FLAC), завантажується в теку «SYNDICATE Єва — оригінали» на Drive і лише після підтвердження видаляється із сервера;
- файл, який не вдалося прочитати, або коли немає куди класти оригінал, лишається на сервері, і картка це каже.

Відео, MP3 і подібні вже стиснуті: без втрат їх не зменшити, тож вони йдуть на Drive як є.

Каталог агента веде на картку. Агенти читають картку: спершу `summary`, далі потрібну частину тексту.

### Що треба для запису оригіналів на Drive

Єві потрібен вхід Google з правом лише на свої файли (`drive.file`), як в Алекса:

```bash
cd /opt/syndicate && python3 scripts/syndicate_vault.py set-google-oauth eva <файл клієнта OAuth> --shred
cd /opt/syndicate && python3 scripts/syndicate_vault.py google-device-login eva
```

Клієнт OAuth можна взяти той самий, що в Алекса (TV and Limited Input). Без цього файли з бота конвертуються, але оригінали лишаються на сервері.

## Порядок на Drive у межах теки SYNDICATE (19.11.2026)

Андрій: усе завантажене має бути розкладене й на Drive, у межах теки «SYNDICATE».

1. На Drive одна тека **«SYNDICATE»**, у ній **«Вхідні на опрацювання»** (Єва створила її 19.11). Завантажуй туди з телефона чи ПК (застосунок Google Drive).
2. Поділись текою **«SYNDICATE»** (цілою) із сервісним акаунтом Єви як **«Редактор»**: Єві треба право переносити файли. Видаляти вона нічого не буде.
3. Що відбувається: дзеркало Єви копіює нове з «Вхідних на опрацювання» в Obsidian → Єва визначає агента й тему → робить Markdown-картку (відео й аудіо розшифровуються, довгі матеріали отримують розділ «Аналіз») → оригінал на Drive переїжджає з «Вхідних на опрацювання» у `SYNDICATE/<той самий шлях, що в Obsidian>`, наприклад `SYNDICATE/Сем/Матеріали/Форекс` → копія на сервері видаляється.
4. Теку «SYNDICATE Єва — оригінали», куди Єва кладе файли з бота, можна один раз перетягнути всередину «SYNDICATE».

Відео з Drive зараз потрапляють у картку як розшифровка звуку й аналіз; зображення з відео (що показано) додамо через Gemini наступним кроком.

## 3. Головний висновок: розрив у серці задуму

Задум Андрія (перше повідомлення): *«пам'ять кожного агента довести до ідеалу,
економія токенів — пріоритет, щоб агент пам'ятав усе, не перечитуючи діалог»*.

У діалозі це перетворилося на архітектуру 4-рівневої пам'яті з SKILL.md —
і саме цей шар у коді **не реалізований**, а той, що є, **не замкнений у цикл**:

```
src/agents/eva.py:116   save_episode(...)      ← Єва ПИШЕ в пам'ять
                        get_recent_episodes()  ← 0 викликів
                        semantic_search()      ← 0 викликів
```

Перевірка по агентах (виклики читання пам'яті):

| Агент | Читає пам'ять? |
| :--- | :--- |
| eva | ✗ |
| fin | ✗ |
| doc | частково (1 виклик) |
| kira | ✗ |
| marshal | ✗ |
| sam | ✗ |

**Наслідок:** 5 із 6 агентів щоразу стартують з нуля. Це не Синдикат із пам'яттю
й характерами, а **роутер задач зі скілами**. Гірше: `save_episode()` працює, тобто
токени й дискове сховище витрачаються на дані, які ніхто не читає — це пряме
порушення принципу Zero-Waste, зафіксованого в тому ж діалозі.

`MemoryManager` при цьому **уміє читати**: `get_recent_episodes(limit=20)`,
`semantic_search(limit=5)`, HNSW-індекси, Redis-кеш, checkpoint'и, кеш відповідей.
Тобто для замикання циклу не треба нічого будувати — треба **викликати наявне**.

## 4. Що зроблено добре (не для компліменту, а як факт)

1. **Sentinel → аліас Маршала.** Коли Андрій 04.10 запитав «навіщо палити токени
   на незрозумілого підлеглого?» — це було виконано бездоганно: `sentinel.py` став
   re-export `MarshalAgent`, усі перевірки — детермінований Python, **0 токенів**.
   Рідкісний випадок, коли зауваження людини втілили точно.
2. **Дедуплікація кокпіта** — справді зроблена: `cockpit.html` і `syndikat_cockpit.html`
   є симлінками на `static/cockpit.html`, а не трьома копіями по 2.7 МБ.
3. **Реєстр поверхів** (`src/floors.py`) — єдине джерело правди; резервні поверхи 3–6
   явно позначені `reserved`, ніщо не мовчить про свою відсутність.
4. **Правило «ніколи не вигадуй дані» реально працює** — сесія 9 знайшла й закрила
   5 шарів, де відсутність даних перетворювалась на оцінку (найгірший: `news_shield`
   відмовляв **у бік дозволу**, 80/100 без veto).
5. **Специфікації з діалогу справді в репо**: `eva_core/`, `marshal_core/`, `sam_core/`,
   `architect_core/`, `fin_core/`, `doc_core/`, `SYNDICATE_AIP.md`.
6. **Інженерна гігієна**: живі SQL-тести з PostgreSQL+pgvector, CI, HITL-поверхня
   підтверджень, per-device токени зі скоупами, SSE-стрімінг.

## 6. Куди пішли дві доби (репл. ~230–259, 04–05.10)

Полірування кокпіта: аватар, димка, потім сфера з YouTube Shorts — три ітерації
заміни анімації, сповільнення лупа на 80%, кольорові спектри для 6 агентів.

Це гарна робота, але вона йшла **при заблокованому деплої**: Redis не стартує
з паролем-плейсхолдером, бекапів немає, пам'ять не читається. Порядок робіт
був перевернутий: спершу те, що видно, а не те, без чого не запуститься.

## 8. Питання, які лишаються відкритими

1. **Tetragon/eBPF** — залишаємо в специфікації як Фазу 2 чи прибираємо?
   На рівні коду його немає, а для роботи потрібен доступ до ядра, що прямо
   суперечить поточному `docker-compose.yml` (`read_only`, `no-new-privileges`,
   `cap_drop`). Обіцяти в документі те, чого не буде — це те саме «вигадування».
2. **Клієнтський додаток** (`apps/`) — його має будувати Antigravity, але там
   лише 2 файли контракту. Це наступний крок чи відкладаємо?

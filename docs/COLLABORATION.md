# Як Claude Code і Codex працюють разом (19.11.2026)

Два інженери, один репозиторій, один замовник (Андрій). Мета: працювати паралельно й не ламати одне одному роботу.
Правила Андрія (`docs/OPERATOR_RULES.md`) і `AGENTS.md` діють для обох.

## Ролі

- **Claude Code — архітектор.** Вирішує, як будується система, розподіляє задачі, рев'юїть PR Codex, зливає PR у
  `main` за словом Андрія. Гілки `feat/…`, `fix/…`, `docs/…`.
- **Codex — інженер.** Вносить правки в будь-яку частину репозиторію (`src/`, `tests/`, `tools/`, `docs/`, `apps/`) за
  задачею від Андрія або архітектора. Гілки `codex/<що>`. Пропонує архітектурні зміни в PR або HANDOFF, а не вносить
  їх мовчки.
- **Андрій** ставить задачі обом, вирішує суперечки, каже «зливай».

## Дошка задач — відкриті PR

1. На початку задачі: `git pull`, кінець `docs/HANDOFF.md`, список відкритих PR.
2. Одразу створи гілку й **чернетку PR** (draft) з назвою задачі й переліком файлів, які збираєшся міняти. Список
   відкритих PR і є дошкою: хто, що, які файли.
3. **Не редагуй файли, які вже є в чужому відкритому PR.** Якщо без цього ніяк — напиши в HANDOFF «Запит до Claude
   Code / до Codex» і чекай, або попроси Андрія вирішити.
4. `docs/HANDOFF.md` редагують обидва: дописуй лише в кінець, свій розділ. Конфлікт у ньому вирішує той, хто зливає.

## Перевірки й рев'ю

- Перед тим як прибрати позначку draft: `bash tools/check.sh` на сервері (Codex — `ssh syndicate-codex`, див.
  `docs/CODEX_SERVER.md`). Червоні ворота = PR не готовий.
- **Перехресне рев'ю:** PR Codex читає Claude Code, PR Claude Code може прочитати Codex (за проханням Андрія чи
  архітектора). Знахідки — коментарем у PR, а якщо немає доступу до коментарів, то розділом «Рев'ю PR #N» у HANDOFF.
- Зливає в `main` лише Claude Code і лише після слова Андрія. Codex у `main` не пише й не зливає.

## Що потребує Андрія, хоч би хто з нас працював

Compose, nginx, Vault, UFW, SSH, користувачі сервера, гроші, публікації, видалення, секрети. Деплой на сервер робить
Андрій.

## Стиль

Документація українською; код, коментарі й коміти англійською (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`).
Наприкінці задачі — розділ у `docs/HANDOFF.md`: що зроблено, що ні, ризики.

## Patch recipe (лише для окремого patch, який справді передано)

Звичайний `git apply` заборонений. Спершу переконатися, що patch призначений цьому checkout
і потрібен; якщо так — застосовувати 3-way, а при конфліктах обирати patch-версії через
`--theirs`:

```bash
git apply --3way -p1 /path/to/received.patch
conflicts="$(git diff --name-only --diff-filter=U)"
if [ -n "$conflicts" ]; then
  while IFS= read -r path; do
    git checkout --theirs -- "$path"
    git add -- "$path"
  done <<< "$conflicts"
fi
git diff --check
git status --short
# Переглянути повний diff; потім перевірити зміни:
.venv/bin/python -m pytest tests/ -q
bash tools/check.sh
```

Якщо 3-way не може застосувати patch або дерево/конфлікти неочікувані — зупинитися й
дослідити базу; не переходити на звичайний `git apply`, `reset` чи масове видалення файлів.
Не видаляти patch-файл, якщо це не погоджений тимчасовий артефакт.

## Найважливіше про середовище

**У пісковиці немає `docker`** — тому всі контейнери, образи й мережеві шляхи
**не перевірялися запуском**, лише парсером Compose і тестами. Це не «проблема, яка
зникне сама»: на сервері вона перетворюється на **перший у житті запуск**, тобто на
найдовший етап з правками. Тому:

* піднімати стек **по одному сервісу** (postgres/redis/vault → embeddings → eva-agent → решта),
  щоб збій був ізольований, а не «вісім unhealthy одразу»;
* докладний чек-ліст першого запуску з таблицею «симптом → причина → дія» — у
  `docs/SESSION_11_HANDOFF.md` §8.2;
* закріплені теги образів (`n8nio/n8n:1.68.0`, `hashicorp/vault:1.15`, `nginx:1.25-alpine`)
  можуть зникнути з реєстру — це перше, що варто перевірити при помилці `pull`.

## Обов'язкові обмеження

* **Ніколи не вигадувати дані.** Відсутність = `{"status": "unavailable", "value": None, "warning": ...}`,
  ніколи не `ok`. Демо-дані — лише з `synthetic: True` + warning і за явним env-прапорцем.
* **Ніколи не «лагодити» тест**, щоб він пройшов — кожен тест фіксує реальний виправлений дефект.
* Гроші/ордера/перекази, видалення даних чи пам'яті, security, production deployment та інші
  критичні зовнішні дії — лише після явного людського підтвердження; email — тільки чернетки.
  Будь-яке розширення прав, політик, сервісів чи ресурсів потребує аналізу й схвалення Андрієм.
* Межі каталогів: `apps/` — **тільки Antigravity**; `src/ deploy/ tests/ config/` — **тільки Arena Agent**.
* Ніколи не редагувати `main` одночасно з іншим агентом; у `main` потрапляє лише зелене за `tools/check.sh`.
* Документи — українською; код/коментарі/ідентифікатори — англійською; коміти — англійською.
* `datetime.utcnow()` заборонено — лише `datetime.now(timezone.utc)`.
* Записувані файли — лише через `src/data_paths.py` (`EVA_DATA_DIR`); секрети — лише через
  `src/vault_paths.py`; PII маскується перед зовнішнім LLM (`src/pii.py`); пошта — чернетки без відправки.
* **Комітити й пушити негайно** — пісковиця переклоновується, локальні коміти зникають.
* Деплой — **на сервері** (локальна машина відхилена користувачем).

## Пастки середовища

* Мережа вибіркова: `github.com`, `raw.githubusercontent.com`, CDN-дзеркала → `000`;
  **`pypi.org` працює**, тому `pip install` доступний. Якщо GitHub недоступний — читати файли
  через зовнішній веб-інструмент на raw-URL `…/refs/heads/main/<файл>`.
* Локальний клон може бути **shallow** — `git merge-base` / `--is-ancestor` дають хибні
  результати, не роби висновків про «розбіжність гілок».
* `docker` недоступний → Compose/Vault/Redis-шляхи в пісковиці не відтворюються, перевіряються
  лише скрипти й логіка.
* Два агенти пишуть репозиторій паралельно — перенумеровувати backlog, ніколи не перезаписувати чуже.

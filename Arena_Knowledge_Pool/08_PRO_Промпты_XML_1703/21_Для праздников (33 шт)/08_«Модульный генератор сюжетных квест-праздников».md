### 📋 Повний текст структурованого XML-промпту:
```text
# Prompt: «Модульный генератор сюжетных квест-праздников»

<CONTEXT>
Ты — системный дизайнер сюжетных праздников. Нужно не просто написать один сценарий, а создать модульную систему: базовый мир и несколько сюжетных “модулей”, которые можно включать или выключать, чтобы адаптировать квест-праздник [повод] под разные условия и аудитории.

<ROLE>
— Архитектор нарративной системы (сеттинг + модули).  
— Конструктор квестов, который думает параметрами и вариативностью.  
— Помощник ивент-агентства: по твоему описанию команда может быстро собирать сценарии для разных клиентов.

<STEPS>
1. Определи базовый мир и тон:
   - Кратко опиши сеттинг, главный конфликт и атмосферу (без лишней детализации).  
   - Убедись, что сеттинг можно “переодеть” под разные форматы (семейный/корпоративный/дружеский).

2. Используй Tree-of-Thoughts:
   - Придумай 3 разных идеи для базового мира, совместимых с [поводом].  
   - Оцени каждую по критериям: гибкость, уместность, простота реализации.  
   - Выбери одну и чётко обозначь, почему именно она лучше.

3. Сконструируй модули:
   - Определи 4–8 независимых (или слабо зависимых) модулей:  
     * Модуль знакомства гостей.  
     * Модуль основного расследования/поиска/испытаний.  
     * Модуль лёгкой активности (вставка, если нужно “разрядить” обстановку).  
     * Модуль для детей или менее активных гостей.  
     * Модуль финала/награждения и т.п.  
   - Для каждого модуля:
     * цель;  
     * сюжетная роль;  
     * пример 1–2 заданий;  
     * требования к реквизиту и пространству;  
     * с кем модуль конфликтует (что нельзя ставить рядом) и с чем хорошо сочетается.

4. Применяй RAG:
   - Если пользователь предоставляет [знания_о_бренде] / [факты_о_имениннике] / [внутренние_шутки],  
     опиши, как каждый модуль можно этим “перекрасить” (примеры: переименовать роли, адаптировать задания, встроить факты).

5. Введи параметризацию:
   - Для каждого модуля укажи варианты под:
     * маленькую группу (до 10 человек) и большую (30+);  
     * короткий праздник (до 2 часов) и длинный (4+ часов);  
     * спокойный и активный формат.  

6. Self-Consistency + Reflexion:
   - После описания модулей создай таблицу совместимости (какие связки модулей рекомендуешь для разных форматов).  
   - Проверь, нет ли логических дыр (например, финал без внятной завязки).  
   - Предложи 2–3 “рецепта сборки” праздников:
     * “Семейный вечер на 2 часа”;  
     * “Корпоративный квест на 3 часа”;  
     * “Детско-взрослый микс”.  
   - В разделе Reflexion кратко оцени сильные и слабые стороны системы, предложи идеи для будущих модификаций.

<CRITERIA>
— Система должна быть:
  * понятной для не-эксперта (ивент-менеджер сможет применить без глубоких знаний драматургии);  
  * гибкой (легко убирать/добавлять модули без потери смысла);  
  * адаптируемой под разные аудитории;  
  * реалистичной по ресурсам (не требовать экзотического реквизита по умолчанию).

— Обязательно указывай, какие модули подходят при строгих табу из [табу-темы] (например, только “безопасный юмор”).

<INFO>
Пользователь задаёт:
- [повод]  
- [формат_клиента]: (семейный / корпоративный / детский / смешанный)  
- [диапазон_гостей] и [возрастные_группы]  
- [длительность]  
- [уровень_готовности_гостей]: (готовы выступать / только участвовать без выступлений / могут включаться выборочно)  
- [знания_о_бренде] или [факты_о_имениннике] (по желанию)  
- [табу-темы]

<OUTPUT>
Выведи:
1. Описание выбранного базового мира (1–2 абзаца) и краткое сравнение с двумя отвергнутыми вариантами.  
2. Перечень модулей (таблица: модуль → цель → сюжетная роль → требования → рекомендации по использованию).  
3. Варианты адаптации модулей под разные аудитории и длительность.  
4. Таблицу совместимости модулей (можно в текстовом виде).  
5. 2–3 примерных “рецепта сборки” праздников для разных форматов.  
6. Раздел Reflexion: самопроверка системы и идеи по её дальнейшему расширению.
```

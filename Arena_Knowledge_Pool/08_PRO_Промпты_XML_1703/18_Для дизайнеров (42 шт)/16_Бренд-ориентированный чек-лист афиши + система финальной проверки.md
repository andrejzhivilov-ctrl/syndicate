### 📋 Повний текст структурованого XML-промпту:
```text
# Prompt: Бренд-ориентированный чек-лист афиши + система финальной проверки

<CONTEXT>
Задача — составить такой список визуальных элементов афиши, который:
- сохраняет и подчёркивает бренд (логотип, фирменные цвета, шрифты, стиль);
- не перегружает афишу, но делает её узнаваемой;
- даёт понятную систему финальной проверки перед печатью/публикацией.

<ROLE>
Ты — бренд- и арт-директор:
- следишь за тем, чтобы афиша была визуально цельной;
- помогаешь встроить элементы айдентики без перегруза;
- даёшь простой чек-лист для финального контроля качества макета.

<STEPS>
1. Проанализируй входные данные из <INFO>:
   - какой бренд (корпоративный, личный, фестивальный и т. д.);
   - насколько жёсткий брендбук;
   - где будет использоваться афиша.
2. Составь список визуальных элементов, разделив на группы:
   - А. Брендовые элементы (логотип, фирменные цвета, шрифты, паттерны, маскоты и др.).
   - Б. Информационные элементы (название, дата, место, формат, спикеры/артисты).
   - В. Элементы призыва и взаимодействия (CTA, QR-коды, ссылки, контакты).
   - Г. Сервисные/юридические элементы (партнёры, дисклеймеры, возрастные ограничения).
3. Для каждой группы:
   - перечисли элементы;
   - коротко поясни, как они взаимодействуют с брендом (усиливают/могут ослабить).
4. Определи иерархию важности:
   - какие элементы должны быть всегда (даже при минимальном формате);
   - какие могут отключаться при ограниченном месте.
5. Сформируй «Систему финальной проверки» (ReAct + Reflexion):
   - Шаг 1 (Reasoning): сформулируй список простых вопросов, по которым можно пройтись по макету (например: «Понятно ли за 3 секунды, что это за бренд и что за событие?»).
   - Шаг 2 (Action): выведи чек-лист, где можно мысленно поставить галочку напротив каждого пункта.
6. Добавь рекомендации по сохранению целостности бренда:
   - что нельзя менять (например: логотип, основные цвета);
   - в чём можно быть более гибким (фон, иконки, дополнительные иллюстрации).
7. Выполни итоговую Reflexion:
   - проверь, нет ли противоречий (например, слишком много обязательных элементов для маленьких форматов);
   - при необходимости сократи/перегруппируй элементы и укажи изменения.

<CRITERIA>
- Чёткое разделение элементов на группы (бренд, информация, CTA, сервис).
- Есть иерархия важности: «обязательные» и «опциональные» элементы.
- Сформирован понятный финальный чек-лист для проверки макета.
- Уделено отдельное внимание бренду: что охраняется жёстко, что — гибко.
- Использованы подходы Reflexion и ReAct для повышения качества финального результата.

<INFO>
Пользователь заполняет:
- Тип бренда: [корпоративный / личный / продуктовый / фестивальный].
- Наличие брендбука: [строгий / базовые элементы / нет].
- Формат афиши: [печать А3/А4, билборд, лента, сторис, баннер, email].
- Обязательные элементы по требованиям партнёров/юристов: [логотипы спонсоров, дисклеймеры, возрастные ограничения и пр.].

<OUTPUT>
Выведи результат в формате:
1. Краткое описание подхода (2–4 предложения).
2. Группировка элементов по категориям (бренд / информация / CTA / сервис).
3. Иерархия важности: таблица или списки «обязательно / желательно / можно убрать».
4. Система финальной проверки: чек-лист из 7–10 пунктов.
5. Краткие рекомендации по сохранению целостности бренда при разных форматах афиши.
```

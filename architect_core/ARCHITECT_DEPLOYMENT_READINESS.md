# Підготовка Архітектора — контрольний список v0.2

**Стан пакета:** ідентичність і default-deny профіль підготовлені; не до activation.
**Порядок:** Єва сформована першою; Архітектор — наступний профіль (n8n-чернетки). Інші агенти мають лише порожні маніфести, доки їх не буде сформовано окремо.

## Зроблено в цій фазі

- Підтверджено окремий профіль `architect` (не лише слот).
- Ідентичність: інженерний архетип, не live CTO. Задачі лише Андрій; Єва не призначає; звіт Єві — payload.
- Маніфест `prepared_not_enabled`, порожні grants, модель не вибрана.
- Workflow-контракт: `active=false`, n8n не control plane.
- Тести: policy deny без grant; ізоляція namespace від Єви.

## Рішення цієї сесії (без розширення прав)

| Питання | Рішення |
|---|---|
| Профіль зараз? | Так. |
| Перший capability? | Не видавати. Ідентичність ≠ grant. |
| Історичний LangGraph `ArchitectAgent`? | Залишити як історичний код/тести; **не** з’єднувати з `AgentDispatcher` і не вважати активацією профілю. |
| Vault `architect → mcp`? | Не копіювати в `services_enabled`. Не змінювати стару мапу в цій фазі. |

## Не готово / не виконувалося

- Hermes runtime, модель, prompt у живому профілі Hermes.
- Будь-який capability / resource scope / service.
- Live n8n, credentials, активація workflow, GitHub write, Telegram.
- Відключення історичного оркестраторного handler (окрема зміна, якщо знадобиться).

## Умови наступного go/no-go

1. Зелений `bash tools/check.sh`.
2. Окреме точне схвалення **одного** capability id, якщо взагалі потрібен runtime.
3. Hermes і n8n live — лише після явного дозволу Андрія.

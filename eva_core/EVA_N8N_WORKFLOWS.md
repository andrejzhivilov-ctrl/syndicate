# Майбутній n8n workflow Єви — чернетка вимог

**Погоджений час нічного аналізу:** `0 3 * * *`, `Europe/Kyiv`.
**Стан:** workflow не створений і не активований; source provider не налаштований, публічного `nightly_analysis` маршруту немає. Будь-який request-body прапорець не може довести дозвіл або активувати виконання. Архітектор розроблятиме систему на n8n в наступній фазі.

## Планований workflow: `EVA-NIGHTLY-ARCHIVE`

1. Trigger: 03:00 локального часу `Europe/Kyiv`.
2. Викликати контрольований Eva endpoint для нічного звіту; не передавати в prompt значення секретів.
3. Джерела: тільки матеріали Єви та явно дозволені текстові сегменти. Не читати всі агентські/особисті зони за замовчуванням.
4. Якщо джерело, модель чи Obsidian недоступні — статус `unavailable`; не створювати фальшивий успіх.
5. Валідувати звіт: джерела, дати, статуси `confirmed/proposal/unknown`, відсутність секретів та unsupported claims.
6. Низькочутливий короткий підсумок заархівувати з позначкою `generated_unconfirmed`; чутливе або неповне — лише до черги ручного перегляду. Нічний підсумок не стає підтвердженою пам’яттю й не індексується як така.
7. Записати мінімізований технічний audit status без текстів діалогів і приватного payload.

## Заборонено в цьому workflow

- Публікувати, активувати чи змінювати інші production workflows без окремого підтвердження.
- Читати/створювати/редагувати/ділитися n8n credentials від імені Єви чи Архітектора.
- Зберігати секрети у параметрах, URL, expression, code-node, execution data або звичайних логах.
- Видаляти чи очищати джерела/пам’ять після архівації автоматично; для видалення спершу потрібне погоджене точкове HITL-підтвердження.
- Активувати email, браузер, календар, геолокацію, дзвінки чи інші інтеграції цим workflow.
- Доручати завдання іншим агентам без прохання Андрія.

## Перед activation

- Obsidian mount/path і права ще мають бути підтверджені.
- Credentials вводить Андрій через контрольовану панель; workflow отримує лише посилання на credential, а не значення.
- Розробка спочатку в staging на синтетичних даних; окремий human review перед production activation.
- Перевірити execution-data retention/redaction, доступи до workflow і rollback.
- `deploy/docker-compose.yml` та production не змінювати в межах цього профілю.

# Marshal — розбір досьє CSO v4.0 (ідентичність ≠ grants)

**Дата розбору:** 2026-10-09.
**Джерело:** досьє «MARSHAL (CSO)» від Андрія + історичний `MARSHAL_FULL_SPEC.md`.
**Чинний профіль:** `config/agents/marshal.profile.json` — `prepared_not_enabled`, порожні grants.
**Правило:** жоден рядок цього файлу не є capability, моделлю, ботом чи host control.

Попередня чернетка свідомо звузила Маршала до «опису меж». Нижче — повний розбір досьє: що беремо в ідентичність, що лишається доктриною без enforcement, що заборонено записувати в профіль.

## 1. Хто він: архетип і сутність — в ідентичність

| Твердження досьє | Статус у чернетці |
|---|---|
| Позивний MARSHAL (CSO), Поверх 10, Security Cornerstone | ідентичність: назва й місце в карті агентів |
| Холоднокровний комендант / слідчий контррозвідки | ідентичність: характер |
| Голос: сухий, сталевий, лаконічний; рапорти `[STATUS: …]` | ідентичність: стиль (без вигаданих статусів) |
| Підпорядковується **виключно Андрію** | ідентичність + робоче правило |
| Єва — CEO, але не скасовує Marshal | **доктрина**, не live veto (див. §2) |
| Кредо v4.0: ініціатива ≠ злочин; злочин — виконання без дозволу | ідентичність |
| Zero Trust: зовнішній вхід ворожий, доки не доведено зворотне | ідентичність / метод оцінки, не сканер |
| Soft Anomaly: слідчий, не кат; пауза й запит логіки | ідентичність / майбутній протокол; зараз немає права ставити процеси на паузу |
| Непідкупність: prompt injection, лестощі, «соціальна інженерія» не змінюють політику | ідентичність |
| `[ANDRII_IMMUTABLE]`: чужі агенти не перезаписують вказівки Андрія | **доктрина deny**; Marshal зараз сам не має права читати чужі файли |

## 2. «Абсолютне право вето» — не grant

Досьє: Marshal володіє абсолютним вето на будь-які дії будь-якого агента, включно з Євою.

Це **не** записується в `capabilities`. Зараз у Маршала нуль grants, тож вето **не існує в runtime**.

Якщо колись буде enforcement, окремий id (наприклад `policy.veto`) має бути:

- точний scope (які агенти, які action class);
- HITL Андрія на саме надання права;
- Dispatcher на маршрутах Marshal;
- явна заборона Єві скасовувати *вже видане* рішення Marshal.

До того часу відповідь Маршала на «заблокуй Єву / freeze / lockdown» — `[STATUS: DENIED | GRANT ABSENT | HITL REQUIRED]`.

## 3. Дев’ять рівнів Defense-in-Depth — карта амбіцій, не «закрито»

У FULL_SPEC таблиця OWASP позначена «✅ Закрито». У репозиторії це **неправда як поточний стан**. Тут рівні — backlog інфраструктури, не обов’язки живого агента.

| Рівень | Зміст досьє | Статус |
|---|---|---|
| 1 | Cloudflare WAF, DDoS, GeoIP, rate limit | інфра хоста; не Marshal grant |
| 2 | UFW, Fail2ban, port knocking 7777→8888→9999 | інфра хоста; **не вигадувати** knock-послідовність як секрет у git |
| 3 | Suricata, Falco, ClamAV 02:00, RKHunter | інфра; не вмикати з профілю |
| 3.5 | Tetragon eBPF in-kernel SIGKILL | **Фаза 2**; не реалізовувати в цій гілці |
| 4 | Docker non-root, read-only FS, E2B | інфра / sandbox платформи; не host control Маршала |
| 5 | Vault, JWT TTL 15 хв, RBAC | Vault уже в репо як окремий шар; Marshal не отримує `services_enabled` |
| 6 | сегментація пам’яті, rollback, n8n HMAC | платформа; Marshal namespace лише `agents/marshal`, і то без memory grant |
| 7 | LLM-Guard, SkillSpector / MCP audit | інструменти не підключені; модель не вибрана |
| 8 | Sentyr ML, canary tokens, HoneyMCP | **Sentinel/Sentyr виключені**; пастки не ставити |
| 9 | Soft Anomaly, HITL, Kill Switch | HITL — платформне правило; kill switch **не live** |

Маршал **не** рапортує, що рівні 1–9 працюють.

## 4. Добовий цикл — не розклад cron

| Слот | Досьє | Чернетка |
|---|---|---|
| 02:00 ClamAV / RKHunter | хост-скан | не ставити job |
| 03:00 аудит пам’яті Єви / snapshot | читання чужого namespace | **deny** (і в Єви memory grant порожній) |
| 04:00 CVE-радар (середа) | NIST/GitHub | не підключати мережевий радар |
| 21:00 Security Report → Єва | між агентами без прохання Андрія | **deny** (агенти не призначають задач одне одному) |
| 24/7 outbound veto, n8n HMAC, HITL черга | live enforcement | немає grants |

## 5. Арсенал — не вибирати й не вмикати

| Елемент | Чому не в профіль |
|---|---|
| Tetragon / Falco / Suricata / Chrony | host / Фаза 2 |
| HashiCorp Vault як «серце ключів Маршала» | Vault — платформа; Marshal не читає секрети інших |
| Claude Haiku / Sonnet | `model_status=not_selected`; не вигадувати модель |
| LLM-Guard, SkillSpector | не встановлені |
| Sentyr, canary, HoneyMCP | Sentinel виключений; deception не вмикати |
| E2B sandbox | платформний шар, не capability Маршала |
| `@marshal_security_bot` | `inbound_channels.telegram.enabled=false`; bot_id не вигадувати |
| Kill Switch: freeze / network sever / total lockdown | `live_modes.host_control=false`; оркестраторний `emergency_lockdown` = deny |
| GeoIP UA/PL/DE | геолокація вимкнена |

## 6. Anti-SPOF — беремо як **deny-межі** ідентичності

Це єдиний блок досьє, який уже збігається з порожніми grants:

- не читати внутрішні тексти робочих папок інших агентів — лише метадані, і то коли з’явиться окремий scope;
- не змінювати `EVA_CORE_PERSONA.md`;
- не видаляти й не правити audit logs (append-only / WORM — інфра, не право Маршала «керувати логами»);
- не правити власний вихідний код;
- зміна ядра Marshal — лише Андрій, окремим HITL / SSH, не через чат агента.

Щотижнева звірка хешу власного коду — **не** вмикати як job.

## 7. Що змінюємо в пакеті після цього розбору

- Persona і runtime prompt: архетип, голос, кредо, підпорядкування Андрію, zero-trust до зовнішнього тексту.
- Явна заборона рапортувати живий стек, DEFCON, LOCKDOWN_ACTIVE, «всі рівні закриті».
- Grants, сервіси, модель, Telegram, host_control — без змін (порожньо / false).

## 8. Що потребує окремого «так» Андрія (не робити зараз)

1. Будь-який capability id.
2. Dispatcher на маршрутах Marshal.
3. Модель.
4. Telegram-бот (окремий bot_id + allowlist).
5. Host / Tetragon / lockdown.
6. Право читати логи чи пам’ять інших агентів.
7. Право вето на Єву чи інших.

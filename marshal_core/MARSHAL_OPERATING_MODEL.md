# Marshal — операційна модель v0.4 (чернетка, не grants)

**Статус:** пропозиція «для початку». Нічого з цього не увімкнено.
**Профіль:** порожні `capabilities` / `resource_scopes` / `services_enabled`.
**Пов’язано:** `MARSHAL_HITL_CONTRACT.md`, `MARSHAL_ACCESS_BOUNDARIES.md`.

Андрій описав старт: вето, окремий Telegram, жовтий/червоний, кнопки як у HITL, моніторинг економно (або n8n без втрати продуктивності), контроль виходу в інтернет і витоку, щоденний стислий звіт через Єву + розгорнутий у Маршала, пропозиції скілів з кнопками, база знань / архів / Drive. Голос (TTS) — сумнів; тут **ні**.

Нижче — конкретна модель. Це не activation і не copypaste в поле grants.

## 1. Принцип старту: спочатку бачити, потім зупиняти

«Контроль всюди» на старті = **спостереження метаданих**; HITL і вето — лише на **критичну загрозу**, не на кожен вихід в інтернет.

Порожні grants інших агентів уже fail-closed ріжуть невидані дії (`AgentPolicy`). Маршал не дублює це LLM-ом на кожен пакет.

Три шари (увімкнення — окремі «так»):

| Шар | Що робить | Зараз |
|---|---|---|
| A. Observe | метадані дії/виходу (агент, клас дії, dest-клас, час, deny/allow) | не зібрано |
| B. Alert + HITL | пуш/кнопки **лише критичне**; жовте — у добовий бриф, не в чат | бот вимкнений |
| C. Enforce veto | стоп лише критичного ходу (не пошук за командою Андрія) | `policy.veto` не видано |

Без шару A шар C не вмикати.

## 2. Вето (пропозиція, «ти сам»)

Marshal **ніколи** не ветирує Андрія. Андрій — єдиний, хто може дозволити червоний HITL. Єва **не** скасовує рішення Маршала/HITL.

Вето — не «вимкнути Синдикат» і не пропускник «чи можна вийти в інтернет».

**Пряма команда Андрія «знайди / подивись в інтернеті»:** Маршал **не блокує** і **не питає**, чи випускати агента. Лише шар A (метадані). Алерт — тільки якщо під час цього ходу є **критична загроза** (витік секрету, підміна політики з веб-сторінки, спроба встановити скіл/MCP, deploy, гроші, delete, вихід не на пошук а на exfil).

Не питати HITL за: новий URL, новий домен пошуку, звичайний web fetch у межах цього прохання.

Вето/червоний HITL — стоп **одного критичного ходу**:

- витік (секрет, повний payload, чужий namespace);
- встановлення скіла, MCP, сервісу, розширення прав;
- production deploy, фінансове виконання, delete;
- egress, який **не** є виконанням прямого прохання Андрія (exfil, невідомий webhook, злив ключів).

Не входить у вето: чат Андрій↔агент, читання власного namespace, **пошук/перегляд в інтернеті за явним проханням Андрія**.

Процедура червоного:

1. Хід ставиться на паузу (платформа, не eBPF).
2. Андрію — картка HITL (див. контракт кнопок).
3. Таймаут → **deny** (не allow).
4. Allow пише audit: хто, що, на який один хід (не безстроковий grant).

Жовтий: не блокує і **не пушить у Telegram**. Лише лічильник у добовому брифі. Soft Anomaly без експлойту — у бриф, не допит Андрія на кожен крок.

Поки `policy.veto` не видано, Маршал лише **рекомендує** стоп. Оркестраторний `emergency_lockdown` лишається deny.

## 3. Telegram-бот (окремий канал, не Єва)

Кандидат: окремий inbound Marshal, не чат Єви. `bot_id` / username / chat id **не вигадувати**. У профілі: `enabled=false`, порожній allowlist = deny.

Рівні:

| Рівень | Коли | Кнопки | Таймаут |
|---|---|---|---|
| жовтий | аномалія без експлойту; звичайний інтернет-пошук за командою Андрія | немає пуша; лише бриф | немає блокування |
| червоний | критична загроза: витік, skill/MCP/grant, deploy, гроші, delete, exfil | Погодити / Відхилити / До ознайомлення | deny |

Тіло алерта: агент, дія, ризик, **без** секретів і сирих payload.

## 4. Моніторинг і токени (не 24/7 LLM)

На кожну подію — детермінований лічильник (клас дії, dest, deny/allow). Без тіла запиту в LLM.

LLM Маршала — лише на червоному HITL або коли Андрій просить розгорнутий звіт.

n8n: **не** control plane і не джерело прав. Кандидат — неактивний workflow, який збирає вже записані лічильники/алерти в стислий бриф. Live API вимкнений.

Cloudflare: не для збору внутрішніх метрик агентів. Кандидат пізніше лише як WAF/rate-limit **публічного** входу (webhook), якщо такий з’явиться. Внутрішній egress моніториться проксі/логами хоста, не GeoIP.

Будь-який контакт агента зі світом і будь-який HTTP(S) — у шар A як метадані. Повні відповіді інтернету в пам’ять Маршала не класти (витік).

## 5. Звіти: Єва стисло, Маршал повністю

Єва **не викликає** Маршала. Агенти не ставлять задач одне одному.

Контракт як у `EvaAgent._compose_briefing`: Єва бере `agent_data.marshal` **лише з payload**. Немає поля — «дані відсутні», не «SECURE».

| Артефакт | Хто бачить | Зміст |
|---|---|---|
| щоденний brief | Єва в ранковому брифі, якщо scheduler поклав payload | 5–10 рядків: жовті/червоні за добу, denies, HITL open, без секретів |
| full report | лише Андрій, прямий запит Маршалу | розгортання інцидентів, аргументи, що не ввійшло в brief |

Scheduler, який копіює brief у payload Єви — окреме n8n «так», не право Маршала писати Єві в namespace.

## 6. Скіли й підключення

Маршал не вмикає скіли й не пише в `services_enabled`.

Новий навик / MCP / «треба вивчити» → картка `SKILL_PROPOSAL`. Коли з’явиться сканер (кандидат: NVIDIA SkillSpector `--no-llm`, див. `MARSHAL_CANDIDATE_CATALOG.md`) — score в картку, без секретів. До того поля `scan: немає`. Оптом сторонні skill-packs не ставити.

## 7. База знань, архів, Drive

| Місце | Призначення | Зараз |
|---|---|---|
| `agents/marshal` | платформна пам’ять | namespace зарезервовано, memory grant немає |
| `marshal_core/knowledge/security/` | read-only корпус (OWASP тощо) | `sources: []`, не ingest |
| архів | HITL-рішення, briefs, пропозиції | не монтовано |
| Google Drive | робочий стіл Маршала | `folder_id=null`, credentials не в профілі |

Drive не є джерелом прав. Секрети в Drive не класти.

## 8. Голос

Стиль рапорту (сталевий текст) — так. TTS / `live_modes.voice` — **ні**, доки Андрій окремо не попросить.

## 9. Що треба окремим «так» (порядок)

1. Шар A: куди писати метадані (без тіл, без секретів).
2. Telegram: реальний bot_id + chat allowlist від Андрія, не з моделі.
3. n8n-агрегатор brief → payload Єви (workflow `active=false` до команди).
4. Drive folder, створена Андрієм.
5. `policy.veto` з точним списком action class — лише після Dispatcher на маршрутах Marshal.
6. Cloudflare — лише якщо з’явиться публічний ingress.

Не в цьому списку і не «для початку»: Tetragon, lockdown, Sentyr, HoneyMCP, Haiku/Sonnet, читання текстів Єви.
